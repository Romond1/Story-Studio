# Startup and media loading investigation

Measured isolated Electron projects with actual media files and 180/600 assets. The 600-asset baseline opened all 200 pool video thumbnail decoders, including offscreen videos. Registry/dependency collection and display naming together averaged about 4 ms. Native open/import handlers took tens of milliseconds on this local fixture. Initial workspace readiness was about 1 s; first media preview about 1.4–1.5 s. The reported 5–6 s delay was not reproduced with these local fixture files, so that exact improvement is not claimed.

Changes:

- `main.tsx` lazy-loads only the chosen lesson or legacy workspace and immediately shows loading feedback. The entry script is now about 1.53 kB before shared dependencies/workspace chunks; the unused editor is deferred.
- `MediaRegistryCache` publishes immutable checked batches instead of withholding all URLs. Current Edit/Live background IDs receive priority, concurrency stays bounded at 32 and filesystem/grant checks remain unchanged. Retired loads cannot publish.
- `useMediaRegistry` exposes checked partial URLs while retaining pending until completion; UI publications are limited to once per 100 ms plus final completion. Hosted editor catalogues and derived image generation still wait for the full catalogue.
- Pool and timeline thumbnails share viewport IntersectionObservers that respect ancestor clipping. Offscreen videos do not open a source; scrolling loads them and leaving the viewport releases their source/decoder. Timeline scene visuals mount near the visible strip only. The 600-asset profile reduced initial pool decoders from 200 to 1; scrolling, hover seek and cleanup were verified. The final isolated profile measured workspace readiness 1.01 s and first preview 1.44 s (baseline 1.00 s / 1.47 s), so decoder reduction is the strongest demonstrated result, rather than a large measured startup speedup. Twenty new small fixture imports displayed cards in 0.35 s and a scrolled newly imported preview in 0.84 s; large real files may differ.
- Autoplay audio ownership is keyed to actual track URLs/settings, not resolver callback identity, so progressive batches cannot repeatedly stop/restart playback. Compact headings keep their existing dimensions regardless of lazy CSS order.

No physical media files, authored asset IDs, names, order, counts, or scene references are changed. Copying large video files to the project still incurs physical disk I/O. This work does not bypass safe media access validation or remove duplicate handling.

Validation: `scripts/media-loading-profile.cjs` records native startup/open/import timings, backend IPC durations, main-thread long tasks and thumbnail-decoder counts. Set `STORY_PROFILE_ASSETS=600`, `STORY_PROFILE_OUTPUT=media-loading-large-after.json`, and `STORY_PROFILE_VERIFY_LAZY=1` for the large-library loading/scroll/seek/cleanup regression. Reports are under ignored `output/`. Early baseline importPreviewMs measured any available preview; the final profiler explicitly scrolls to and waits for newly imported media, so those two import-preview numbers should not be compared directly. Unit regressions cover early batches, priority, immutable snapshots, retired loads and audio stability. Full unit suite: 654 passed; renderer type check and renderer/main builds passed. Native pool, density, trim, and bubble range checks cover editing and playback workflows.
