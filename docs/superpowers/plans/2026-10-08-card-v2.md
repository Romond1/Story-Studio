# Card V2 C1–C4 implementation plan

Date: 2026-10-08. C0/C0.5 accepted by user. Preserve dirty checkout and production episodes; no migration or C5/C6.

Goal: author reusable multi-face cards/sets and Recall & Reveal booster activities, with deterministic shared rendering and independent occurrence state.

Architecture: optional ProjectData.cardsV2 discriminated module (`engine: card-v2`, `version: 1`). Explicit cardActivityRef booster items point to placements. Typed definitions/faces/styles/sets/activities/instances/placements remain authored; Control owns a token-guarded occurrence session. Render plans carry resolved lines/font/boxes/style and selected visible face; Present never creates state. Existing legacy runtime remains isolated and legacy preservation forSave passes V2 module through unchanged.

Implementation units:
- [x] C1/C3: src/shared/cardsV2.ts domain, validation, templates, duplication, stable face references, session commands and tests.
- [x] C2: src/shared/cardV2Render.ts deterministic bounded text layout and student-safe plan parser; src/renderer/cardsV2/CardV2Scene.tsx renders exact logical plans, reduced-motion transitions.
- [x] C4: src/renderer/cardsV2/CardV2Editor.tsx and CSS provide card/set/activity library, face editing, templates, tags, usage counts, duplication, frame and card geometry, drag-resize, image asset selection.
- [x] Integration: ProjectData optional module, main load/save reject unsupported/invalid versions without writing; explicit sequence ref normalization; Core target/navigation, Edit entry, runtime controls, shared scene projection, passive Present and asset readiness.
- [x] Tests: domain, runtime stale commands/independent reuse, deterministic fit multilingual/overflow, projection safety/recovery and geometry, persistence round-trip/no legacy V2 creation. Existing card/runtime/persistence suites, builds, and disposable-copy audit.
- [x] UI verification: browser/Electron disposable project exercise creation/edit/reuse/save/teach/reveal/reset, capture evidence. No production saves.
- [x] Final report: architecture, implemented workflow, tests/evidence, checklist and deferred scope. Stop.

Design decisions: prefer bounded optional module to modifying A/B types; prefer existing presentation relay to a separate engine; use explicit saved logical frames (1280x720 default), no responsive reflow. Each activity contains authored instances linked to cards and optional source set. Each placement references an activity; duplication remaps activity/instances. Sets are reusable references, not live state. Activities use stable per-instance initial/reveal face IDs; face labels have no semantic meaning. No implicit circular cycling. Unknown module versions fail safely on open/save. Story overlay is deferred if it requires parallel layout authority.
