# Card V2 research: current architecture

Research date: 2026-10-07. This document describes the **current dirty working tree**, including the uncommitted [cardRuntime.ts](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts), presentation, and history refactors. It is source inspection, not an implementation or a browser test report. No source, Episode, project data, or existing changes were modified for this research. Source references below link to current workspace files and line numbers; shorthand subsequent line references refer to the immediately preceding file.

## What changed relative to the older architecture warnings

- **Confirmed:** Teach drag and shuffle no longer directly mutate the authored ACard library. `ACardSystem.updateInstance` routes Teach through `runtime.move`; `handleShuffle` only calls `updateACard` in Edit ([src/renderer/acards/ACardSystem.tsx:37-45,69-73](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardSystem.tsx:37)). Overlay dragging has the same Edit/Teach split ([src/renderer/App.tsx:2158-2169](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:2158)).
- **Confirmed:** Shuffle is now a Control-owned Core command in `CardRuntime.shuffle`, not randomization in Present or during rendering ([src/shared/cardRuntime.ts:43-58](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:43)). Randomness is consumed at the command boundary; snapshots carry resulting positions.
- **Qualified correction:** Shuffle still receives a measured element size ([ACardStageRenderer.tsx:103-122](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardStageRenderer.tsx:103) → [ACardSystem.tsx:69-72](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardSystem.tsx:69)). In Teach that element normally lives inside `LogicalSceneFrame`, so `clientWidth/clientHeight` describe the logical CSS canvas, not its scaled on-screen bounding rectangle ([src/renderer/StaticScene.tsx:12-23](D:/AI/GitHub/Story-Studio/src/renderer/StaticScene.tsx:12); [src/renderer/App.tsx:5071,5103](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:5071)). It is inaccurate to call all current Teach shuffles dependent on external monitor pixels. The authored model still lacks an explicit saved canvas, and Edit geometry can differ from Teach geometry.
- **Confirmed:** ACard timers no longer start independently on each renderer mount. Core creates `startedAt` once per occurrence/reference, and Control and Present both receive it ([src/shared/cardRuntime.ts:19-21](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:19); [src/renderer/acards/ACardSystem.tsx:113](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardSystem.tsx:113); [src/renderer/ActivityScene.tsx:26](D:/AI/GitHub/Story-Studio/src/renderer/ActivityScene.tsx:26)). Each renderer merely samples `Date.now()` to display elapsed time ([ACardStageRenderer.tsx:87-101](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardStageRenderer.tsx:87)).
- **Confirmed:** [TeachStateProvider.tsx](D:/AI/GitHub/Story-Studio/src/renderer/acards/TeachStateProvider.tsx) remains in the repository but has no consumer/import sites under `src`. The same is true of [BCardInstanceRenderer.tsx](D:/AI/GitHub/Story-Studio/src/renderer/acards/BCardInstanceRenderer.tsx). Neither is the current active state or rendering authority. Repository-wide symbol searches, plus the active `ACardSystem` imports and component path, establish this; their mere presence should not drive V2 design.

Positions are interpreted as **percentage centers**; width/height are absolute CSS/logical units. This is established by render conversion, rather than documented in the type ([src/renderer/acards/StageInteractable.tsx:62-68](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:62)). There is no authored canvas size, aspect-ratio contract, layout mode, grid/pile/stack model, ordered deck model, named preset, variant object, or per-face placement override in these interfaces. `flags` is an untyped future escape hatch, not an implemented override mechanism.

ACards are not the only BCard host. Slides and sections each have `bCardInstances`; boost sequence items inherit them as well ([src/shared/types.ts:101,123,191](D:/AI/GitHub/Story-Studio/src/shared/types.ts:101)). Current App selects a host for story or boost and binds a separate `overlays` occurrence ([src/renderer/App.tsx:1693-1734](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:1693)). ACard references and standalone BCard placements are distinct concepts.

### Store, project ownership, history

`CardSystemProvider` is a prop-backed CRUD adapter, not an independent persisted database. It receives the two project libraries and an `onChange` callback ([src/renderer/store/CardStore.tsx:27-37](D:/AI/GitHub/Story-Studio/src/renderer/store/CardStore.tsx:27)). Internal refs are synchronously advanced on each `emit`, avoiding the documented create-BCard-then-update-ACard stale-library overwrite (`:38-54`). Updates replace entire definitions (`:92-94,142-144`).

App's callback writes both libraries into `ProjectData`, sanitizes related references, and marks dirty ([src/renderer/App.tsx:4022-4044](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:4022)). Current `setProject` records authored changes into `ProjectHistory`, so library edits participate in the existing project-level history rather than a separate card undo stack ([App.tsx:860-871](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:860); undo application at `:2280-2301`). Teach Core changes bypass this authored path.

Deletion is two-layered: deleting a BCard removes it from every ACard in CardStore ([CardStore.tsx:146-163](D:/AI/GitHub/Story-Studio/src/renderer/store/CardStore.tsx:146)), then App sanitizes slide/section/boost standalone placements and invalid ACard references ([App.tsx:470-546,4033-4037](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:470)). Deleting an ACard only deletes its library entry in CardStore (`:96-100`); App removes references. Any future caller that mounts CardStore without App's callback must provide equivalent cross-document cleanup if desired.

`project.json` persists the full `ProjectData` object with an updated timestamp, through a temp-file write/sync/rename path ([src/main/main.ts:224-247](D:/AI/GitHub/Story-Studio/src/main/main.ts:224)); Save As copies project media/folders before final publication (`:212-221,901-933`). There is no separately serialized card runtime in this save path. The current project schema is version 4 ([src/shared/types.ts:127](D:/AI/GitHub/Story-Studio/src/shared/types.ts:127); [src/main/main.ts:626-635](D:/AI/GitHub/Story-Studio/src/main/main.ts:626)).

### Migration and validation limits

Main normalizes standalone BCard placements on sections/slides/boost items, including legacy `bCardRef` conversion. Legacy top-left pixels are converted against assumed 1280×720 and default 270×390 card size ([src/main/main.ts:280,297-318](D:/AI/GitHub/Story-Studio/src/main/main.ts:280)). Current instance normalization supplies IDs, clamps percentage positions, enforces size ≥40, rounds z-index and preserves `flags` as an object (`:321-358`). Legacy standalone boost card items are attached to neighboring sequence content; the normalizer can synthesize a migrated prompt card when necessary (`:478-521`).

**Confirmed gap:** `normalizeProjectData` normalizes sections/slides/boost items and returns `...data`, but does not run corresponding library-wide normalization of `aCardLibrary`, nested ACard placements, BCard faces, or styles ([src/main/main.ts:536-635](D:/AI/GitHub/Story-Studio/src/main/main.ts:536)). App's reference sanitizer processes slide/section/boost references, not all ACard internals ([App.tsx:470-546](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:470)). Type declarations are not runtime validation. A V2 migration must explicitly own library validation rather than assume existing load normalization covers it.

Validation currently differs by path: Main size floor 40 ([main.ts:344-346](D:/AI/GitHub/Story-Studio/src/main/main.ts:344)), overlay App normalization floor 40 ([App.tsx:461-466](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:461)), drag-resize widget minimum 60×80 ([StageInteractable.tsx:171-174](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:171)), numeric ACard editor uses HTML `min={40}` but writes parsed values directly ([ACardEditor.tsx:680-708](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardEditor.tsx:680)), Core checks only finite positive dimensions ([cardRuntime.ts:34-35](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:34)). Numeric input `min` alone is not normalization.

## Authored, session, and local UI state

| State | Owner/lifetime | Persistence |
|---|---|---|
| Card definitions, faces, authored placements, timer configuration | `ProjectData` through CardStore/App | `project.json`; project history |
| Active board/boost/story selection and target revision | `PresentationSession` reducer in Control | Select fields included in local live-session snapshot |
| Per-occurrence placement copies, reveal state, shuffle motion, timer start | `CardRuntime` held by `useCardRuntime` | In memory; projected to Present; not project-save or live-session storage |
| Selected BCard, click action, shuffle speed/acceleration, measured stage size | Component/App React state | Mainly local; global overlay click action is included in live-session snapshot |
| Present window visual tree, display clock, loaded-image readiness | Present renderer | Rebuilt from snapshot and authoritative time anchors |

`useCardRuntime` is keyed by session/project/runtime generation; changes replace the Core object ([src/renderer/useCardRuntime.ts:12-18](D:/AI/GitHub/Story-Studio/src/renderer/useCardRuntime.ts:12); [src/renderer/App.tsx:1594](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:1594)). `CardRuntime` indexes occurrences by `[activeOccurrence, ref]`, allowing the same global ACard/BCard to have separate live states at different uses ([src/shared/cardRuntime.ts:12-21](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:12)). `boardBinding` uses ref `board` by default or actual story/boost reference IDs; standalone cards use `overlays` ([App.tsx:1732-1734,1817-1823](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:1732)).

`ensure` clones authored placement objects/position/size on first use, compares serialized authored instances on subsequent calls, preserves runtime placement when authored input is unchanged, replaces changed instances, and prunes removed reveal states ([cardRuntime.ts:19-28](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:19)). Editing even a non-position authored instance field changes its serialization and therefore restores that instance's full authored placement. Core does not have a per-field merge policy.

Commands capture `[occurrenceId, targetRevision]`; Core rejects a command whose target no longer matches current activation ([useCardRuntime.ts:17-27](D:/AI/GitHub/Story-Studio/src/renderer/useCardRuntime.ts:17); [cardRuntime.ts:31-45](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:31)). This protects delayed drag callbacks after navigating away and back. Occurrence state itself remains when navigating away; return finds the existing entry. Maps have no eviction/reset API beyond replacing the Core on project/session generation change.

Project close/open paths increment the runtime generation ([App.tsx:2529,2598](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:2529)). `createLiveSessionSnapshot` saves selection/click-action but not `CardRuntime.instances`, four reveal booleans, shuffle motion, or ACard `startedAt` ([App.tsx:2742-2768](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:2742)). A resumed application session therefore does not recover those card interactions. The old type comment “resets continuously” ([types.ts:571](D:/AI/GitHub/Story-Studio/src/shared/types.ts:571)) is less precise than the current occurrence-scoped retention behavior.

Local `ACardSystem` state includes selection, click action, measured stage size, and shuffle configuration ([ACardSystem.tsx:25-29](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardSystem.tsx:25)). These are not keyed/reset explicitly on `aCardId`. Top-level Boards uses an unkeyed `ACardSystem` ([App.tsx:5073-5083](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:5073)), whereas referenced cards in story use `key={ref.id}` ([App.tsx:5788](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:5788)). **Inferred UX risk:** a board switch in the unkeyed branch can retain stale selected-instance/tool preference state even though Core state is correctly separated.

## Editing, duplication, rendering, and interaction

### Editor surfaces and duplication semantics

`ACardEditor` combines stage identity/background/text/timer controls, library browsing, placed instances, and selected reusable BCard editing. The selected instance is resolved against the ACard and then its global definition ([src/renderer/acards/ACardEditor.tsx:124-140](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardEditor.tsx:124)). Front/back edits update the global BCard and consequently every reference; the editor explicitly states this (`:172-195,663`). `BCardEditor` offers a separate global-library editor ([src/renderer/acards/BCardEditor.tsx:57-85,189-216](D:/AI/GitHub/Story-Studio/src/renderer/acards/BCardEditor.tsx:57)).

Adding an existing BCard creates a new placement with its own ID, 160×220 size, staggered percentage center and ascending z-index ([ACardEditor.tsx:143-154](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardEditor.tsx:143)). Standalone overlay creation instead defaults to 270×390 ([src/renderer/App.tsx:2010-2018](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:2010)); these are different authoring defaults.

- Duplicate ACard: new stage ID, cloned background and placement IDs/geometry/flags, **same linked BCard definition IDs** ([CardStore.tsx:102-120](D:/AI/GitHub/Story-Studio/src/renderer/store/CardStore.tsx:102)). Editing a BCard shared by the copied stage still affects the original.
- Duplicate BCard in library: new definition ID/name, deep copied faces; image/audio IDs remain references to the same assets ([CardStore.tsx:165-177](D:/AI/GitHub/Story-Studio/src/renderer/store/CardStore.tsx:165)).
- Duplicate selected to stage: first duplicates the reusable BCard definition, then creates a new placement pointing at the duplicate, offset by +4 percentage points and raised z-index ([ACardEditor.tsx:205-223](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardEditor.tsx:205)). This differs from duplicating only a linked placement.
- Section duplication gives story references and standalone placements new IDs while retaining their referenced ACard/BCard IDs ([src/shared/sectionMutations.ts:39-69](D:/AI/GitHub/Story-Studio/src/shared/sectionMutations.ts:39)).

V2 should make these distinct “linked placement” and “independent content copy” semantics explicit; there is already shared-content behavior to preserve during migration.

### Rendering pipeline

Active rendering is `ACardSystem` → `ACardStageRenderer` → `StageInteractable` → two `BCardFace`s. Standalone placements use `BCardInstanceLayer` → `StageInteractable`. Present directly uses the passive versions of the same components, supplying card definitions rather than requiring CardStore ([src/renderer/ActivityScene.tsx:23-28](D:/AI/GitHub/Story-Studio/src/renderer/ActivityScene.tsx:23); [ACardStageRenderer.tsx:36-42](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardStageRenderer.tsx:36); [StageInteractable.tsx:37-43](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:37)).

ACard backgrounds support transparent, solid, gradient and image. Offset/scale/blur are inline CSS ([ACardStageRenderer.tsx:48-80](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardStageRenderer.tsx:48)). Half-stage moves background and BCard content into the bottom half (`:128-134,165-170`); the stage text layer remains a separate full-container positioned element (`:136-162`; [acard.css:32-56](D:/AI/GitHub/Story-Studio/src/renderer/acards/acard.css:32)). There is no shared explicit layout engine: typography/background/content rules are distributed through JSX/CSS.

Faces combine a full-cover image, overlaid plain text and a bottom-right emoji ([BCardFace.tsx:11-54](D:/AI/GitHub/Story-Studio/src/renderer/acards/BCardFace.tsx:11)). Image fit is hard-coded `object-fit: cover` ([acard.css:141-148](D:/AI/GitHub/Story-Studio/src/renderer/acards/acard.css:141)). There is no face image focal-point/contain control in the schema. Card radius, shadow, borders, face border, text padding/shadow, cover appearance and zoom scale are predominantly hard-coded ([StageInteractable.tsx:115-123,178-195](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:115); [acard.css:116-159,162-193](D:/AI/GitHub/Story-Studio/src/renderer/acards/acard.css:116)). Theme/style extension would need to span both data and these shared renderers.

Flip is CSS rotateY with a fixed .5s transition; blur is 8px + brightness(.6); zoom is scale(1.4); cover is an overlaid question mark ([acard.css:103-113,162-193](D:/AI/GitHub/Story-Studio/src/renderer/acards/acard.css:103)). These booleans combine independently. The transform does not change the instance's stored size. **Inferred constraint:** collision/fit/bounds operate on the unzoomed base rectangle, not the enlarged visible footprint or optional board shell.

`displayMode='board'` means an extra shell 35 units beyond each card edge, not a second ACard/layout type ([StageInteractable.tsx:178-182](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:178)). Its footprint is excluded from Core shuffle collision rectangles ([cardRuntime.ts:48-54](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:48)).

### Move, resize, stacking

`StageInteractable` uses `react-rnd` only for active Edit. Teach and passive display use a plain absolute-positioned div ([StageInteractable.tsx:22-38](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:22)). Teach uses pointer capture and its own drag handler, divides screen delta by actual measured transform scale, clamps within stage dimensions and updates Core positions (`:91-112`). Edit converts Rnd drag/resize results to percentage centers and clamps centers to 5–95% (`:138-170`). Teach clamps by card bounds, not that 5–95% rule.

Rendering independently clamps top-left geometry into the measured stage without writing the correction back (`:62-68`). An oversized card anchors at zero and may still overflow. Edit resize changes placement width/height and center; it does not affect every BCard definition. `BCardInstanceLayer` sorts by z-index (`:88`), and each positioner gets its placement z-index ([StageInteractable.tsx:115-116](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:115)).

**Inferred stacking risk:** zoom's `z-index:1000` lives on the inner wrapper ([acard.css:166-168](D:/AI/GitHub/Story-Studio/src/renderer/acards/acard.css:166)) while each outer positioner has its own z-index/transform ([StageInteractable.tsx:23,115-133](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:23)); zooming a lower card may not put it above another outer stacking context. This needs browser verification, not a claim of reproduced behavior.

### Shuffle

Current algorithm sorts larger rectangles first; for each card, tries up to 350 random candidate positions with an 8-unit margin from already placed candidates; converts accepted center to percentages; and falls back to the card's prior position if no slot succeeds ([cardRuntime.ts:43-58](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:43)). It has no packing guarantee or success-count/error report. A fallback card is not inserted into `placed`, so later successes can overlap it. Cards larger than the frame are not rejected: sampling uses `max(0, frame-cardSize)` and can produce percentages beyond 100, later visually clamped. These are direct algorithm properties, not UI reproductions.

Teach shuffle stores `CardMotion {durationMs,easing,key,startedAt}` with placements. Present receives the same movement and positions. The renderer derives remaining CSS transition time from `startedAt` ([StageInteractable.tsx:123](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:123)), but the payload has no previous-position path or animation progress. **Inferred limit:** a newly mounted/reopened Present will generally appear at the final layout, not reconstruct an in-flight shuffle path. `key` is transported but not used as an animation restart key in `StageInteractable`.

Edit shuffle explicitly persists the runtime result into ACard instances ([ACardSystem.tsx:72](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardSystem.tsx:72)). The edit screen also puts a 330px inspector inside the `ACardSystem` flex layout (`:99-103,125-143`), whereas Teach omits it. **Confirmed structural difference/inferred visual consequence:** with the same outer logical frame, Edit content has less width, so percentage centers and absolute card dimensions can yield different spacing/overlap after switching to Teach. This is the remaining geometry issue worth designing around; it is narrower than the old “all Teach shuffle writes screen pixels into the library” warning.

### Timers and media

ACard timer config is authored, but `startedAt` belongs to the occurrence. Core `ensure` is called during App rendering regardless of app mode ([useCardRuntime.ts:19-20](D:/AI/GitHub/Story-Studio/src/renderer/useCardRuntime.ts:19); [App.tsx:1817-1823](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:1817)), not on explicit timer Start. Therefore a card can accumulate time while previewed in Edit, while timer visibility is off, and while the occurrence is away. Enabling a timer later uses the old anchor. There is no ACard pause/resume/reset command in `CardBinding` ([useCardRuntime.ts:5-10](D:/AI/GitHub/Story-Studio/src/renderer/useCardRuntime.ts:5)). This behavior follows directly from current code and should be a deliberate V2 decision.

Do not conflate ACard timers with Break timers: Break uses `TimerAnchor {isRunning,startTime,accumulated}` and `timerSeconds`; ACard uses a single occurrence timestamp and a separate display calculation ([src/shared/cardRuntime.ts:3,7-10](D:/AI/GitHub/Story-Studio/src/shared/cardRuntime.ts:3); [src/renderer/ActivityScene.tsx:7-10](D:/AI/GitHub/Story-Studio/src/renderer/ActivityScene.tsx:7); [ACardStageRenderer.tsx:87-101](D:/AI/GitHub/Story-Studio/src/renderer/acards/ACardStageRenderer.tsx:87)).

Images resolve asset IDs to project `media://` URLs in Control ([App.tsx:5079-5081](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:5079)); Main constrains resolved media to the project root ([main.ts:638-656](D:/AI/GitHub/Story-Studio/src/main/main.ts:638)). Projection includes images referenced by both authored faces of used cards and their backgrounds, including the currently hidden reverse face ([src/shared/activityScene.ts:38-57](D:/AI/GitHub/Story-Studio/src/shared/activityScene.ts:38)). Present preloads image dependencies and reports readiness ([src/renderer/present.tsx:95-117](D:/AI/GitHub/Story-Studio/src/renderer/present.tsx:95)).

**Confirmed:** BCard `audioRefId` and `animationPreset` are authorable metadata, but repository-wide searches found no playback/animation consumer beyond their editors/types. The existing renderer does not trigger BCard-specific audio or apply these presets. Student projection intentionally omits both ([activityScene.ts:34,51-56](D:/AI/GitHub/Story-Studio/src/shared/activityScene.ts:34)). Implementing these in V2 would be new behavior requiring an authoritative command/media integration, not merely exposing a hidden existing capability.

## Core / Control / Present integration contract

1. Control's `PresentationSession` resolves active content and occurrence identity. Board/library mode keys by board ID; Boost keys by sequence item ID; story keys by selected section/slide. Resolved kind/content/drawing destination are appended so authored retargeting changes identity ([src/shared/presentationSession.ts:67-160](D:/AI/GitHub/Story-Studio/src/shared/presentationSession.ts:67)).
2. Control `useCardRuntime` binds per-reference state under that occurrence; commands mutate Core and request a Control rerender ([useCardRuntime.ts:12-29](D:/AI/GitHub/Story-Studio/src/renderer/useCardRuntime.ts:12)). This is an in-process authority, not an Electron-main service.
3. App builds `ActivityScene` from authored definitions plus live placement/reveal/clock/movement data in Teach ([src/renderer/App.tsx:1816-1838](D:/AI/GitHub/Story-Studio/src/renderer/App.tsx:1816)). It builds a logical scene frame separately (`:1802-1815,1849-1854`).
4. `usePresentProjection` applies `parseActivityScene`, namespaces media, creates a full target projection and publishes a monotonically revised snapshot ([src/renderer/usePresentProjection.ts:13-40,57-70](D:/AI/GitHub/Story-Studio/src/renderer/usePresentProjection.ts:13)).
5. Electron Main only accepts publishing from Control; it validates/orders snapshots through `PresentSnapshotRelay` and relays them ([src/main/presentWindow.ts:123-131](D:/AI/GitHub/Story-Studio/src/main/presentWindow.ts:123); [src/shared/presentationSnapshot.ts:121-139](D:/AI/GitHub/Story-Studio/src/shared/presentationSnapshot.ts:121)). Present's limited preload exposes subscription/recovery/readiness/media APIs, not project/library mutation ([src/main/presentPreload.ts:4-20](D:/AI/GitHub/Story-Studio/src/main/presentPreload.ts:4)).
6. Present renders `LogicalSceneFrame` plus `PassiveActivities` with pointer interactions disabled ([src/renderer/present.tsx:84-105](D:/AI/GitHub/Story-Studio/src/renderer/present.tsx:84); [ActivityScene.tsx:23-28](D:/AI/GitHub/Story-Studio/src/renderer/ActivityScene.tsx:23); [StageInteractable.tsx:89-92,119](D:/AI/GitHub/Story-Studio/src/renderer/acards/StageInteractable.tsx:89)). Both surfaces use the same percentage/size rendering code and occurrence time anchor.

The projection parser is a critical schema seam: it explicitly rebuilds card/face/instance/state objects, strips teacher/library metadata, includes only required cards/images, strips instance flags, and ignores future fields unless deliberately added ([activityScene.ts:22-57](D:/AI/GitHub/Story-Studio/src/shared/activityScene.ts:22)). Adding fields only to [types.ts](D:/AI/GitHub/Story-Studio/src/shared/types.ts) or Control components would cause them to disappear in Present. `PresentSnapshot` parsing calls this parser again at the transport boundary ([presentationSnapshot.ts:105-106](D:/AI/GitHub/Story-Studio/src/shared/presentationSnapshot.ts:105)).

## V2 integration seams and remaining risks

These are design implications, not proposed source changes in this research:

- Preserve reusable **definition → authored placement → live occurrence** separation. Existing IDs and many host locations are already meaningful; a single generic “card” object would erase semantics.
- Keep Control commands authoritative, Present passive, and authored edits in project history. New layout operations should resolve to explicit placements in Core and project through the current student-safe parser.
- Give geometry an explicit contract. Current hybrid percent-centers/absolute-size, half-stage coordinate space, inspector-reduced Edit frame, oversized cards, zoom/shell footprint and inconsistent minimum sizes are the concrete issues to settle.
- Treat linked-copy versus independent-copy as separate actions; current board duplication retains linked definitions, selected-card duplication detaches content.
- Define timer lifecycle independently from component mount. Current anchor persistence fixes remount drift but does not supply start/pause/reset or a “start on Teach” boundary.
- Centralize a versioned migration/validator for every host plus global libraries. Current standalone normalization does not cover ACard library internals. Preserve old IDs, face/media references and intentional defaults unless migration explicitly transforms them.
- Plan new style/media fields across authored types, editor, renderer, parser and tests. Existing BCard audio/animation fields are not active runtime features.
- Preserve current navigation activation rejection and project generation reset. Extend commands with relevant occurrence/ref/instance identity instead of bypassing Core from new toolbar callbacks.
- Expect session-only card positions/reveal state to vanish after app restart today; do not accidentally promise session persistence from the existing local-storage “restore session” name.
- Keep dead `TeachStateProvider`/`BCardInstanceRenderer` out of new architecture assumptions; any later removal should be a deliberate implementation step, separate from this research.
